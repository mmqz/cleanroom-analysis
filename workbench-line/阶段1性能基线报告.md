# 阶段 1 性能基线报告（四类基准——headless 面）

> **依据**：《文档工作台后续实施计划》阶段 1（先以现有引擎能力建立
> 三类基准 + Canvas 原型已存在故纳入第四类）。
> **口径纪律**：不设性能门禁阈值，只记可复现基线（与 bench_limits
> 同纪律）；数字全部本会话亲跑（release 构建，本沙箱）；测量面与
> 宿主依赖面明确分界——UI 路径延迟待宿主原型补测，本报告为其提供
> 引擎侧下界。**不把未经测量的指标写成承诺**。
> **复现命令**：全部在档（每节首行；mdcore main = `82884cc`）。

## 0. 环境

共享 CPU 沙箱（Linux x86_64，rustc 1.99.0，release profile）；
计时 = Instant；峰值 RSS = /proc/self/status VmHWM。绝对值受环境
影响，**相对结构与量级**是选型决策的输入；宿主原型对照时以同机
同法复跑为准。

## 1. 基准①：长文档与证据侧栏

`cargo run --release -p mdc-workbench --example bench_long_doc -- <场景> <段数> <主张数>`

| 场景 | 规模 | 结果 | 峰值 RSS |
|---|---|---|---|
| 正文摄取（DOCX→指纹+sidecar 发布） | 10k 段 | 44 ms | 51 MiB |
| | 100k 段 | 471 ms | 456 MiB（线性） |
| 绑定登记（含逐笔 sidecar publish） | 10k 段 × 1000 主张 | **54.8 ms/笔** | 55 MiB |
| | 100k 段 × 100 主张 | **494.5 ms/笔** | 457 MiB |
| 选择性失效（refresh_body） | 100k 段 × 100 主张 | 533 ms（含重摄取 471ms） | 459 MiB |
| 来源重验（reverify_source） | 1000 条 | 8.3 ms/条 | 55 MiB |
| 会话重开（sidecar 载入） | 128 KB sidecar | < 1 ms | — |
| 审核报告生成 | 100 主张 | < 1 ms | — |

**发现 ①-1（绑定每笔 O(正文)）**：`propose_binding` 的 fail-closed
纪律 = 每笔重读正文（防 TOCTOU）→ 每笔成本 ≈ 正文摄取时间。批量
导入 1000 主张在 100k 段文档上 ≈ 8 分钟——**UI 批量导入场景需要
会话内批量通道或受控缓存**（当前纪律是安全取舍，如实登记不改）。
**发现 ①-2（选择性失效精确且便宜）**：外部改写 1 段 → 恰 1 条主张
失效（全指纹对照后的差额），失效扫描自身（除重摄取）~60ms@100k 段
——「正文定位到来源」的引擎侧延迟为毫秒级，UI 侧栏刷新无引擎瓶颈。

## 2. 基准②：大表格

`cargo run --release -p mdc-office-io --example bench_limits -- <场景>`

| 场景 | 规模 | 结果 |
|---|---|---|
| 全量读（read_book 全门+typed 网格） | 500k 格（500×1000） | 525 ms / 40 MiB |
| **可视区切片**（50 行×20 列窗口，typed.get_abs） | 万窗 | **2 µs/窗** |
| **C3 单笔编辑提交全链**（读+kind 保持逐格重放+写） | 500k 格 | 读 536 + 重放 64 + 写 492 = **≈1.1 s** |

（既有在档：read4m = 4.4s/279MiB；write1m 流式 vs 非流式 RSS 28× 差。）

**发现 ②-1**：切片读取本身免费（内存网格 2µs/窗）——可视区虚拟化
的引擎侧无瓶颈；**全量读（525ms）是每次打开的固定成本**。
**发现 ②-2（C3 提交下界）**：单笔单元格编辑 = 读改重建全链 ≈1.1s
@500k 格——这正是计划阶段 5「版本化切片 + 局部更新」的量化论据：
表格面要么走**延迟/批量提交**（编辑本地预览 + 显式提交点），要么
后续裁决 C3 升级（当前 t16 裁决维持读—改—重建，此为该裁决的
诚实代价面）。

## 3. 基准③：PDF（既有 perf 门复跑）

`MDC_PDFIUM_LIB=… cargo test --release -p mdc-pdf --features engine-pdfium --test pdfc_perf -- --ignored --nocapture`

**6/6 过**：打开 TTI（500 页）中位 **0.16 ms**；首屏渲染（1000px）
**9.38 ms**（注：编译后冷进程首跑观测 43.7ms——页缓存冷的环境方差，
稳态复跑 8.4–12.9ms 均过 25ms 阈值）；顺序渲染 50 页（800px）p50
**0.62 ms** / p95 **0.82 ms**；全档文本抽取 10.18 ms；抽取吞吐
**56,211 页/s**；翻页 LRU 命中 **0.51 µs** vs 未命中 2.96 ms。

**结论 ③-1**：PDFium 路线全面满足——无需第二套解析真相，无需
共享纹理（计划 §四.3 的「先完成页面缓存和稳定滚动」路径无引擎侧
阻碍）。

## 4. 基准④：Canvas（基准 1k / 压力 10k 双档）

`cargo run --release -p mdc-canvas --example bench_canvas -- <场景> <节点数> <采样数>`

| 场景 | 1k 基准档 | 10k 压力档 |
|---|---|---|
| 装载（AddNode+边，每命令一事务一撤销项） | 7 ms（6 µs/op） | 73 ms（6 µs/op） |
| 拖拽提交（MoveNode） | p50 3 µs | p50 5 µs / p95 8 µs |
| 命中查找（find_object） | ~1 µs | p50 1 µs |
| 删除+撤销复原（同 ID 回归） | — | p50 11 µs |
| **读模型全量快照（objects()）** | p50 **1.0 ms** | p50 **13.3 ms** / p95 14.8 ms |
| 全画布指纹（证据重验最坏面） | p50 2.1 ms | p50 24.3 ms |
| 协同同步（全量差量编码 + 新端应用） | 149 KB / 编码<1ms / 应用 5 ms | 1.5 MB / 编码 6 ms / 应用 61 ms |

**发现 ④-1（模型面无瓶颈）**：拖拽提交/命中/删除复原全部 µs 级
——画布交互延迟不在模型层。
**发现 ④-2（全量快照是渲染面瓶颈候选）**：`objects()` p50 13.3ms
@10k——60fps 帧预算 16.6ms 会吃掉 80%。**增量通道已在位**（integ-r2
事件面 touched 对象 ID）——阶段 5 渲染接入应走 touched 驱动的增量
读，全量快照仅初始装载用；此为渲染器选型对照的关键输入。
**发现 ④-3**：全画布指纹 24ms@10k——证据重验按对象级指纹
（`object_fingerprint`）走增量，全量仅初始登记，量级可接受。

## 5. 前端能力盘点（宿主选型前置——不预判）

- **web/ 桥（在位可用）**：CM6（state/view/commands 6.x）↔
  mdcore-wasm；MD 面编辑可用；PDF 面为独立轻量视图（不经 CM6）；
  Office/Canvas/证据侧栏**无前端面**（headless API 已全备——事件/
  在场/中继/命令接口）。
- **shell-native（蓝图态）**：零依赖结构蓝图（tao+wry+GTK3 设计
  意图注记；R22-a..f 实体 = 开发环境轮）。
- **候选面（按计划双原型对照）**：A = Web 技术桌面（复用 web/ +
  wry 壳——存量代码复用度最高）；B = 原生 UI 候选（Slint/Iced/
  egui/Qt Quick 等——按组件生态/输入法/无障碍/许可/维护成本筛，
  Slint 不因 Kokoa 兼容默认胜出）。
- **对照操作集（计划 §四.5）**：相同正文（长文档滚动+编辑）、
  证据侧栏（失效/重验刷新）、表格（500k 档切片滚动+编辑提交）、
  Canvas（1k/10k 拖拽+快照/增量渲染）——四类基线即对照负载。
- **Windows 7**：单独兼容目标，不阻塞主平台。

## 6. 结论与下一步

1. **引擎侧四类基线全部在档可复现**（命令+数字+环境口径）；无一处
   以未测指标冒充承诺。
2. 三个**结构性行动项**进入阶段 5 议程（均为已知架构的诚实代价，
   非缺陷）：表格编辑提交策略（局部更新/延迟提交裁决）、Canvas
   增量读接入（touched 事件驱动）、证据批量导入通道（会话级缓存）。
3. **下一步（阶段 1 后半）**：双宿主原型（A：web/wry 存量复用；
   B：原生候选一枚）以 §5 对照操作集实测——形成选型记录并定主
   宿主；随后按计划进阶段 2（证据复验）→ 阶段 3（协作完成度收口）
   → 阶段 4-6。
