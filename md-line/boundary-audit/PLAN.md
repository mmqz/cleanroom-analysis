## 0. 为什么做这次审计（问题定义）

线 A 已收官（06 综合报告），D1/D2/D3 三项终裁待用户决断。其中 **D2（双态

## 2. 证据分级规范（全计划统一，报告强制沿用）

| 级别 | 定义 | 标注格式 |
|------|------|----------|
| 【代码确认】 | 主代理或勘察代理亲读源码所见 | `路径:行号` 或 `路径#符号名` |
| 【测试验证】 | 亲跑或亲读测试代码所见 | `套件名::用例名` + 结果 |
| 【文档记录】 | 本仓文档（worklog/STATUS/06 等）既有登记，**尚未代码复核** | `来源文档 §节` |

背书；②性能断言**没有基准数据不得宣称已验证**（现状：perf 门 6/6 全部
PDF 面【文档记录：worklog t2-pdf-e-1】，MD 面基准存在性待 P0 查证）；
③【文档记录】在 P0-P6 执行中被代码确认/证伪时，必须回写修正并登记
差异（基线校准的 Core 交付物）。

## 5. 执行纪律

1. **只读红线**：mdcore 仓零 commit、零工作区改动（勘察用只读工具；如需
   跑测试，跑完 `git status` 必须干净）。唯一写面 =
   `cleanroom-analysis/md-line/boundary-audit/` + `worklog.md`（+ 状态文件
   可开工项一行登记）。
2. **写审分离**（沿用本仓既定纪律）：P1-P6 勘察由子代理执行（按对象分组，
   每个 P 一组或按 O 对象分组，视 P0 实测规模定）→ 每份阶段产物由**新**
   独立复审代理做锚点抽查（比例 ≥20%，抽样覆盖全部关键判断）→ 主代理
   汇总修正 → P7 报告另派终审代理。主代理只派发、监督、汇总。
3. **worklog**：计划登记 = Task `t6-md-boundary-plan`；执行各阶段按
   `t7-md-boundary-p0`…`-p7` 逐阶段追加（或按实际会话轮次合并，但每个
   P 的验收必须可追溯）。
4. **凭据**：克隆 mdcore 与推送本仓均走 GITHUB_TOKEN 环境变量单次传递
   （`tools/push_to_github.sh` 机制，Basic user:token，用毕零残留验证）。
5. **推送与验证**：每完成一个 P（或会话轮）→ commit → push → ls-remote
   验证 local=remote；mdcore 仓仅 ls-remote（只读）。

cleanroom-analysis/

先例）；②公开仓匿名可重取——**工作区重置韧性最优**（mdcore 私有，重置后
凭据未恢复期间报告仍可读）；③审计属分析域，mdcore 仓保持零改动即最干净
的"只读"证据。
