## 0. 为什么做这次审计（问题定义）

线 A 已收官（06 综合报告），D1/D2/D3 三项终裁待用户决断。**v1.2 收缩后，
本轮审计不再服务于"统一引擎/协同架构"的研究目标，而是聚焦一个事实基座：
MD 引擎现有模块的复用性盘点**——哪些模块可作为独立能力被复用（消费者
本轮不预设：画布、PDF 深化、未来产品面均可能）、复用成本几何、复用会
对现有 PDF 载体质量造成什么影响。该基座目前只有文档级记录（worklog 各轮
登记），从未做过一次系统性的、证据分级的模块级审计。本计划填补这个缺口：
产出一份**仓内、简洁、可复核**的复用方案报告。报告定位 = **复用事实与
方案输入，不是架构终裁**：D1/D2/D3 本轮仅记录相关发现（用户 2026-10-12
明确），最终架构裁决由用户后续作出。

**审计的三个必答问题（v1.2 改写，P7 报告必须逐条回答）**：

1. MD 现有模块（事务管线、undo 系统、Block ID、序列化、设置面、会话
   管理、wasm 桥协议、DocumentEngine 集成模式等——**以 P1-P6 实测模块
   清单为准**）中，哪些**可直接复用**、哪些**需要最小适配**、哪些
   **不可复用**？（逐项分类 + 代码证据）
2. 每一项的**适配成本**（内容 + 落点）与**验证标准**（复用后如何验证
   不回归）是什么？
3. 模块复用对 **PDF 质量**有什么影响？（mdc-pdf 既有依赖面 + 任何复用
   改动的波及风险）

协同现状与约束作为**附属登记项**（第四问降级）：只登记现状与约束事实，
零选型（用户原话"协同只调查现状和约束，不进行完整 CRDT 选型"）。

## 2. 证据分级规范（全计划统一，报告强制沿用）

| 级别 | 定义 | 标注格式 |
|------|------|----------|
| 【代码确认】 | 主代理或勘察代理亲读源码所见 | `路径:行号` 或 `路径#符号名` |
| 【测试验证】 | 亲跑或亲读测试代码所见 | `套件名::用例名` + 结果 |
| 【文档记录】 | 本仓文档（worklog/STATUS/06 等）既有登记，**尚未代码复核** | `来源文档 §节` |
| 【推断】 | 由上三级外推的判断 | 依据链必附 |
| 【未知】 | 本轮无法判定 | 附"待查路径"（如何消除该未知） |

纪律：①关键判断（模块归属、机制存在性、语义不变量）必须有前三级之一
背书；②性能断言**没有基准数据不得宣称已验证**（现状：perf 门 6/6 全部
PDF 面【文档记录：worklog t2-pdf-e-1】，MD 面基准存在性待 P0 查证）；
③【文档记录】在 P0-P6 执行中被代码确认/证伪时，必须回写修正并登记
差异（基线校准的 Core 交付物）；④**阻塞记录规则（v1.1）**——无法访问
mdcore 或无法运行门禁时，必须在 baseline.md 与最终报告逐条登记阻塞原因
与影响面，受影响条目保持【文档记录】级并显式标注"本轮未复验"；
【文档记录】仅表示历史文档有此记载，**不得作为当前轮验证的替代**，
禁止以历史报告（worklog/STATUS/gates.md 登记）冒充当前验证结果；
⑤**（v1.2）mdcore 代码结论必须来自本轮实际访问与核验**——克隆后亲读
源码方可落级【代码确认】/【测试验证】，历史文档一律不代答。

## 5. 执行纪律

1. **只读红线**：mdcore 仓零 commit、零工作区改动（勘察用只读工具；如需
   跑测试，跑完 `git status` 必须干净）。唯一写面 =
   `cleanroom-analysis/md-line/boundary-audit/` + `worklog.md`（+ 状态文件
   可开工项一行登记）。
2. **本轮零 commit/零推送（v1.2 用户指令）**：调查方向确认前，两仓均不
   commit、不 push；产物以工作区文件 + 会话回报承载。方向确认后的
   commit/push 策略（恢复 v1 原案"每 P 完成即 commit+push"或另行安排）
   由用户在确认时裁决。风险取舍登记：工作区若再次重置，未提交产物丢失
   （R7），已知悉。
3. **写审分离**（沿用本仓既定纪律）：P1-P6 勘察由子代理执行（按对象分组，
   每个 P 一组或按 O 对象分组，视 P0 实测规模定）→ 每份阶段产物由**新**
   独立复审代理做锚点抽查（比例 ≥20%，抽样覆盖全部关键判断）→ 主代理
   汇总修正 → P7 报告另派终审代理。主代理只派发、监督、汇总。
4. **worklog**：计划登记 = Task `t6-md-boundary-plan`（v1/v1.1）；执行各
   阶段按 `t7-md-boundary-p0`…`-p7` 逐阶段追加（或按实际会话轮次合并，
   但每个 P 的验收必须可追溯）。
5. **凭据**：克隆 mdcore 与（方向确认后的）推送均走 GITHUB_TOKEN 环境变量
   单次传递（`tools/push_to_github.sh` 机制，Basic user:token，用毕零残留
   验证）。凭据不跨会话保留（零落盘纪律）——每轮需要时由用户重新提供，
   缺失时按 §2 纪律④登记阻塞，不以历史报告代答。
