# MD 线 R-1..R-6 逐项处理（reuse-impl 增量轮）

> **性质**：用户指令「MD 线 R-1..R-6 逐项处理，遇产品语义或真机依赖即停」
> 的执行轮。输入 = reuse-impl REPORT §4 登记表 + mdcore main=00ad88b 代码
> 现状复核 + **本会话新证据**（yrs-b D1-a 集成验证边界文档的跨线联动）。
> 处理口径：逐项判定「可实施 / 停-产品语义 / 停-真机依赖 / 无事可做 /
> 维持延后」；产品语义项**不实施**，收敛为裁决问题呈用户。
> **执行纪律**：mdcore 零接触零提交维持（全部六项均落在裁决面或延后面，
> 证据见逐项）；全部锚点本轮亲核。

## 1. 逐项处理记录

### R-1：undo_coalesce_ms 死设置

**现状锚点（本轮亲核）**：
- settings 侧链路齐备：`crates/settings/src/lib.rs`——键定义 :83、默认
  `UNDO_COALESCE_MS_DEFAULT = 1000` :76、界限 `(1, 10_000)` :45、解析
  :302、越界回退默认+警告 :378、TOML 写出 :463；
- 引擎侧硬编码：`crates/mdcore/src/history.rs:20` `pub const COALESCE_MS
  = 1000`，:96 `should_coalesce` 直接引用常量；`History` 无窗字段
  （:55-66 结构体全列）；
- 消费面为零：`COALESCE_MS` 全仓引用仅 history.rs 自身 + settings 文档
  注释 + shell 常量锁测试（r24_settings.rs:362
  `defaults_align_with_core_constants`）；
- **裁决门在档**：REUSE.md §R5 行原文「`undo_coalesce_ms` 为**登记保留
  键**（存储链齐备、当前不驱动引擎行为——**接线属产品裁决**）」。

**处理**：停-产品语义。REUSE.md 的显式裁决门优先——本轮不接线。

**裁决输入补充（本会话新增，供用户决策）**：
1. 【推断】schema 证据倾向 A（接线）：界限 + 默认 + 往返全链已在（保留键
   通常无此 plumbing——B 选项反而要改 schema 语义声明）；接线默认值 =
   现常量 1000 = **默认行为零变化**（纯使能面）。
2. 接线形状（若裁 A）：`History` 加 `coalesce_ms` 字段（serde
   `default = COALESCE_MS` + `skip_serializing`——会话参数非文档状态，
   持久化格式零变化）+ `Core::set_undo_coalesce_ms` + wasm 导出 +
   main.ts 初始化/`mdc-settings-changed` 活应用 + 常量锁测试扩展
   （shell r24 加 `History::default().coalesce_ms() == COALESCE_MS`）。
3. **yrs 联动（B3.2）**：协同域捕获窗（yrs `capture_timeout_millis`）
   计划对齐 mdcore 合并窗 1s——若本地窗变为可配置，适配层应镜像同源
   配置（同一设置键驱动两域），接线时应预留这一点。

### R-2：重开 undo 物化 ID 撞号

**现状锚点（本轮亲核）**：撞号机制实测在档（G4b 现状锁
`t3_reuse_locks.rs:135`：构型 [1,2,3,4]→插 MID(物化5)→删 p3→save→
重开重解析→undo 重插→树内重复 BlockId、注册表覆盖无守卫
`tree.rs:154-156` BTreeMap::insert）；「维持现状+文档」选项**已生效**
（现状锁测试即文档化）。

**处理**：停-产品语义——三选项（register 守卫 / ID 持久化进 meta /
维持现状）行为面各异，非机械可决。

**裁决输入更新（本会话新增，改变裁决范围）**：
- **yrs-b R4.4**：协同域的 BlockId 跨会话保真由 CRDT ID 映射表承接，
  **撞号面在协同域被消解**（ID 永不重编）。因此 R-2 的守卫/持久化选项
  **只剩本地域价值**——若本地域维持现状，R-2 可整体关闭（协同域由
  D1 实施轮的映射表面覆盖）；
- 若选守卫：行为变更面 = 重开 undo 重插路径从「静默树内重复」变为
  「显式失败」——宁缺毋错对齐，但该路径用户可感知（undo 报错 vs
  静默脏树），产品取舍而非纯安全取舍；
- 若选 ID 持久化进 meta：save/open 格式变更（meta 增 ID 清单）+
  重解析分配器改造——六项中最重，且与协同域映射表功能重叠。

### R-3：undo 栈无上限

**现状锚点（本轮亲核）**：`history.rs:56-57` `undo/redo: Vec<Entry>`
无容量约束（push_entry :102-106 直推）；G5 现状锁在档（t3_reuse_locks
头注「undo 栈无上限」）。

**处理**：停-产品语义（容量上限 + 逐出策略 = 显式产品决策）。

**裁决输入补充（本会话新增）**：**yrs-b B3.4** 已在协同域预留栈容量
上限参数（默认无限维持现状，产品裁决后一处启用；yrs `StackItem` 无
内建逐出，实现 = 适配层 observe 面包装）。**建议 R-3 与 B3.4 协同
裁决**（同一产品语义在两域的镜像参数），避免两域栈策略漂移。
