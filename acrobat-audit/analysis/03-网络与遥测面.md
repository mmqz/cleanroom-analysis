# 03 · 网络与遥测面：安装器端点 + 外部情报交叉

> 证据基线：Property 表 313 项、`evidence/msi_strings_mining.json`（36 PE + setup.exe 字符串挖掘）、`evidence/external-research/`（8 组检索，检索日 2026-10-09）。
> 本篇回答：**这套安装/更新链路会连接哪些端点，2026 年的现实行为面是什么**。

## 1. 本地证据端点清单（安装器静态载荷内）

对 36 个 PE 流与 setup.exe 做全部 ASCII/UTF-16 字符串挖掘后，按域归类：

### 1.1 ARM 更新基础设施（Property 表，安装时写入注册表并被 ARM 消费）

| 属性 | 值 | 用途 |
|---|---|---|
| `ARMManifestLocation` | `https://armmf.adobe.com/arm-manifests/win/AcrobatDCManifest.msi` | DC 主更新清单 |
| `ARMManifestLocation2` | `…/win/AcrobatDCManifest2.msi` | 二级清单 |
| `ARMManifestLocation3` | `…/win/AcrobatSCAManifest3.msi` | SCA 清单 |
| `ARMOnDemand_Redirection` | `…/win/ArmOnDemand3.msi` | 按需重定向清单 |
| `ARM_Update` | `https://armmf.adobe.com/arm-updates/win/ARM-NEXT/ARM_update/AdobeARM.msi` | ARM 自更新 |
| `ARM_Update2` / `ARM_Update3` | 同目录 `AdobeARM2.msi` / `AdobeARM3.msi` | ARM 自更新备线 |
| `ARMCheckFrequency` | `72`（小时） | 检查周期 |
| `ARM_PROPERTIES` | `DISABLE_FIU_CHECK=1##IGNORE_TRACK_INTEROP=YES##MIGRATE_FEATURES=YES` | ARM 安装参数（`IGNORE_TRACK_INTEROP=YES` 值得注意：显式跳过互操作跟踪） |
| `DEFAULT_UPDATE_MODE` | `3` | 默认更新模式 |
| `ARPURLUPDATEINFO` | `http://helpx.adobe.com/acrobat.html` | ARP 更新信息链接 |

**结论**：更新面收敛于单一域 `armmf.adobe.com`（清单+更新 MSI 交付）。这是安装器静态载荷中唯一的 Adobe 行为性端点族——网络面集中、可预测、可整体管控。

### 1.2 setup.exe 引导器

UTF-16 字符串中仅 `http://www.adobe.com/go/acrobat_system_reqs_*` 与 `…/go/ARMUpgradeFailedHelp_*`（26 语言的系统需求/升级失败帮助链接）+ DigiCert/VeriSign 证书链 URL。**引导器无隐藏下载端点**——它按 setup.ini 就地链装 MSI/MSP，不拉取远程载荷。

### 1.3 36 个 PE 组件

全部 URL 为 Authenticode 证书链产物（ocsp/crl/cacerts.digicert.com、verisign.com）。唯一例外：ADelRCP.dll 内的 `https://clients2.google.com/service/update2/crx`（Chromium 扩展更新 URL，属 AcroCEF/浏览器集成清理逻辑的引用字符串，非主动连接路径）。域名命中仅 `www.adobe.com`（帮助链接）。

**安装器网络面小结**：静态载荷干净——无遥测收集端点、无激活/授权端点、无数据外发路径；唯一行为端点是更新交付域 `armmf.adobe.com`。（激活/遥测端点存在于安装后的 Acrobat.exe/AGS 等运行时组件中，不在本安装器内——见 §2。）

## 2. 外部情报交叉（2026-10-09 检索，8 组查询）

### 2.1 运行时网络面的权威来源

Adobe 官方企业文档 **"Network endpoints for Adobe apps & services"**（helpx.adobe.com/enterprise/kb/network-endpoints.html，443 端口全量白名单清单）是企业侧端点治理的权威基线；社区侧存在成熟的遥测阻断实践（pihole 版 Adobe blocklist、`a-dove-is-dumb` 等工具、SysAdminDoc/Disable-AdobeTelemetry 的注册表策略+防火墙+hosts 组合方案）。企业处置路径在 04 篇展开。

### 2.2 AGS（Adobe Genuine Service / AdobeGCClient）2025–2026 现状

检索（ags_eol / gcclient / ags_uninstall 三组）未发现任何 Adobe 官方宣布 AGS 停用的证据——**AGS 仍是活跃的正版验证机制**。社区画像（与 02 篇本地证据互补）：

- **行为**：`AdobeGCClient.exe` 由计划任务 `AdobeGCInvoker-1.0` 于**每次用户登录**触发，执行 Adobe 全家桶的正版校验（"check for tampering with any of the software in its suite"——Reddit/thewindowsclub 描述）。
- **CPU 问题持续存在**：Adobe 社区 2025–2026 年仍有 `adobegcclient.exe` 恒定占用 25% CPU、风扇狂转的报告；"Adobe Genuine Software Integrity Service" 高 CPU 报告同样持续（卸载后数日被 Creative Cloud 重装——社区确认的再注入行为）。
- **卸载难度**：官方提供的 AGS 卸载路径（控制面板/清理工具）不完整——"Unable to fully uninstall Adobe Genuine Service: It's apparently missing Adobe Cleanup Utility"（社区原话）；因此出现社区清理脚本（CaptainChicky/Remove-Adobe-Genuine-Client 等）。
- **极端案例**：某用户报告 Adobe 创建"hundreds of scheduled tasks to run GC Invoker"（数百个 GC 调度任务实例——属异常扩散案例，正常应为每登录触发）。

与本地证据的闭合：02 篇发现本 MSI 的 CA 引用中出现 `gccustomhook.exe`——AGS 与安装链的挂钩点在运行期；本 MSI 静态载荷不含 AdobeGCClient，与"AGS 由 setup.exe 链/ARM/CC 在运行期引入"的社区描述一致。

### 2.3 ARM 更新机制在真实系统上的画像（update_task.json）

- `AdobeARMservice` = `armsvc.exe`：服务描述与 MSI 内嵌字符串逐字一致（file.net：*"It is the AdobeARMservice service: Adobe Acrobat Updater keeps your Adobe software up to date"*）。
- 更新自举 = 服务 + 计划任务 `Adobe Acrobat Update Task` 双通道；社区确认"Updater self-updated itself with the latest version… Moving to Task Scheduler makes…"——即 **ARM 具备自更新能力**（对应 Property 表 `ARM_Update*` 三个自更新 MSI URL）。
- 阻断路径：任务计划程序禁用 "Adobe Update" 任务 + 服务改手动（04 篇处置矩阵）。

### 2.4 Acrobat 26 当前已知行为问题（acro26.json + Task 1 检索遗留）

2025–2026 社区高热问题：Acrobat 后台进程悬挂/堆积（"Multiple Adobe Acrobat processes…fails to launch"、"RDS server…after a while"）、以及 Task 1 检索已发现的 **26.002.21931 创建 10,000+ USER 对象耗尽桌面堆** 的个案——与本安装审计互补：安装链路干净，但运行时进程治理是当前版本的真实痛点。

## 3. 网络面分级汇总

| 面 | 端点/机制 | 证据 | 定级 |
|---|---|---|---|
| 安装器静态载荷 | 无行为端点（仅帮助/证书链 URL） | 36 PE + setup.exe strings | 无风险 |
| 更新交付 | `armmf.adobe.com`（4 清单 + 3 自更新 MSI），72h 周期 | Property 表 + Registry 表 | 低（可控：单域） |
| ARM 常驻 | SYSTEM 服务 + 登录任务 + 自更新能力 | ServiceInstall/Control + PE strings | 中（自更新通道） |
| AGS 常驻 | `AdobeGCInvoker-1.0` 任务（登录触发）+ 校验外联 | 外部情报 + gccustomhook 引用 | 中（CPU 侵入 + 再注入） |
| 运行时遥测 | Acrobat.exe/CC 组件遥测端点族 | 官方 endpoints 文档 + 社区 blocklist | 中（需企业策略治理） |

（注：`prod.adobegenuine.com` 等 AGS 端点未出现在本安装器载荷内，故不在本地证据表中；AGS 端点清单以官方 endpoints 文档为准。）
