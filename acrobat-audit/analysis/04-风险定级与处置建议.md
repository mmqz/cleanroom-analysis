# 04 · 风险定级与处置建议

> 汇总 01–03 篇全部本地证据与外部情报，给出分级结论与可执行处置。沿用本系列审计的证据纪律：**每一条结论可回溯到具体表/流/字符串/检索记录；无法证明的不写**。

## 1. 总体结论

| 对象 | 定级 | 依据 |
|---|---|---|
| 安装链路（下载→引导→MSI/MSP） | **干净** | Task 1 四重验证（TLS/Akamai/MD5/Authenticode 签名链）+ 本审计 36 PE 与 setup.exe 字符串面零恶意特征 |
| 安装器静态载荷 | **低** | 无隐藏端点、无休眠触发动作、持久化机制全部在表内明示（ServiceInstall/Registry/CA） |
| ARM 更新基础设施 | **中** | SYSTEM 服务 + 登录任务 + **自更新能力**（ARM_Update×3 URL），单域收敛（armmf.adobe.com）但通道是活的 |
| AGS（AdobeGCClient） | **中** | 登录触发的全家桶校验、社区持续的高 CPU 报告、CC 再注入行为、官方卸载工具链不完整 |
| 运行时遥测 | **中** | 安装后 Acrobat/CC 组件遥测端点族（官方 endpoints 文档收录），默认开启 |
| CRClient 崩溃报告挂接 | **低** | WER 助手指向 Adobe CRClient.dll，崩溃数据流向 Adobe |

**一句话**：与 Task 1 的结论衔接——官方分发链与安装器本体无可指摘；**真实的行为面成本发生在安装之后**（ARM/AGS/遥测三个常驻机制），且全部有对应的关闭或收窄路径（下表）。

## 2. 处置矩阵

### 2.1 企业环境（有策略工具）

| 目标 | 措施 | 键/路径（外部证据源） |
|---|---|---|
| 关闭更新自举 | ARM 双通道：服务改手动/禁用 + 禁用计划任务 | `AdobeARMservice`；Task Scheduler: "Adobe Acrobat Update Task" |
| 停用遥测/PIP | 注册表策略 | `HKLM\SOFTWARE\Policies\Adobe\(product)\(version)\FeatureLockdown`（官方 acrobatetk PrefRef + cloudbuild/community 指南） |
| 禁用更新检查 | ARM 预留策略键 | `SOFTWARE\Policies\Adobe\Adobe Acrobat\<track>\FeatureLockdown`（本 MSI Registry 表亦写入 `PolicyDisableUpdater` 引用，02 篇 §2.4） |
| 端点白名单治理 | 以官方 endpoints 文档为基线，443 出站收敛 | helpx.adobe.com/enterprise/kb/network-endpoints.html |
| 批量部署静默化 | ABCPY.INI/Customization Wizard | `source/ABCPY.INI`（ISX_SERIALNUMBER 等） |
| AGS 全停 | 先断再注入源（CC/产品安装会重装 AGS） | 社区方案（CaptainChicky 脚本）+ 官方卸载路径，需组合使用 |

### 2.2 个人环境（有限手段）

1. **任务计划程序**：禁用 `AdobeGCInvoker-1.0` 与 `Adobe Acrobat Update Task`（若存在）。
2. **服务**：`AdobeARMservice` 改"手动"（更新改为手动触发——注意 Acrobat 26 有安全更新需求，权衡取舍）。
3. **自启动**：任务管理器→启动项，禁用 `Acrobat Assistant (Acrotray)`（不影响 PDF 阅读，仅 Distiller 托盘功能）。
4. **防火墙**（可选）：如需阻断更新域，仅针对 `armmf.adobe.com`——**不要**盲目 hosts 屏蔽全部 Adobe 域（会破坏激活/授权/在线服务，社区方案 a-dove-is-dumb 的区分式阻断是更安全的参考）。
5. **崩溃报告**：如在意，可移除 WER RuntimeExceptionHelper 的 CRClient 挂接（02 篇 §2.3 键位）。

### 2.3 自审计（复现到自己的机器）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Collect-AdobeAutostart.ps1
```

该只读收集器输出 JSON：全部 Adobe 计划任务（含触发器与执行命令）、服务（含运行账户）、Run 键、活动进程（CPU/内存——对照 03 篇的 GCClient 高 CPU 特征）、DNS 缓存中实际解析过的 Adobe 域（近实际连接面）、关键文件存在性与 Authenticode 状态（AGCClient/armsvc/Acrobat/CRClient）。
