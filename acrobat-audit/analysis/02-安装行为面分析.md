# 02 · 安装行为面分析：服务、计划任务、自启动与 336 个定制动作

> 证据基线：`evidence/msi-tables/`（11 张重建表）、`evidence/_behavior_summary.json`、`evidence/msi_strings_mining.json`（36 PE 字符串挖掘）、`source/setup.ini`、`source/ABCPY.INI`。
> 本篇回答：**签名合法的 AcroPro.msi 在一台 Windows 机器上安装时，会创建哪些常驻机制**。

## 1. 服务面：一个自装服务 + 对三个 Windows 系统服务的干预

### 1.1 ServiceInstall（流 #092，16 细胞逐项解码）

| 字段 | 值（来自 MSI） |
|---|---|
| ServiceInstall 键 | `ServiceInstall1.BDCA7721_F290_4124_BBED_7A15FE7694EB` |
| **服务名** | **`AdobeARMservice`** |
| **显示名** | **`Adobe Acrobat Update Service`** |
| 描述 | `Adobe Acrobat Updater keeps your software up to date.`（见 #092 尾部细胞） |
| 绑定组件 | `ARM_armsvc_exe.BDCA7721_F290_…`（其 KeyPath 即 `armsvc.exe`） |

外部交叉验证（`evidence/external-research/update_task.json`、file.net/bleepingcomputer 词条）：`armsvc.exe` 在真实系统上的服务显示名与描述**与 MSI 内嵌字符串逐字一致**——本地证据与真实世界行为闭合。

### 1.2 ServiceControl 全表（7 行，完整重建）

| 控制键 | 目标服务 | Event 位 | 时机语义 |
|---|---|---|---|
| StopArmService… | **AdobeARMservice** | 2 (Stop) | 安装/升级前停掉 ARM 服务（防文件占用） |
| UninstallArmService… | **AdobeARMservice** | 128 (Delete@uninstall) | 卸载时删除服务 |
| ImageAcquisitionService_StopAndStart | **stisvc**（Windows 图像采集） | 51 | 安装扫描仪插件时停-启系统服务 |
| Spooler_StopAndStart（×2 变体） | **Spooler**（打印后台处理） | 51 / 48 | 安装 Distiller/PDF 打印机时重启打印栈 |
| Spooler_StopAndStart_ESRCoEx | Spooler | 48, Wait=1 | 共存模式（保留旧版 Acrobat）打印栈重启 |
| Wsearch_StopAndStart | **wsearch**（Windows Search） | 34 | 注册 PDF IFilter 后重启索引服务 |

**风险评注**：对 `Spooler`/`stisvc`/`wsearch` 的停启属安装期的短暂、可恢复干预（Wait=1 表示等待完成），是打印机/索引集成的常规需求，非驻留后门。真正的常驻面是 `AdobeARMservice`——一个以 SYSTEM 运行、独立于 Acrobat 主程序存活的更新服务。

### 1.3 计划任务：ArmInst.dll 的字符串证据

对 PE 流 `#024`（ArmInst.dll, 1.824.42.0176）与 `#023`（ADelRCP.dll）做字符串挖掘（`evidence/msi_strings_mining.json`）：

```
"Adobe Acrobat Update Task"      ← 计划任务名
"Entered AddTask"                ← 任务创建函数日志
"StartArmService"                ← 定制动作：通知/启动 ARM 服务
"CustomActionInfo: ERROR Encountered: [StartArmService] : : Unable to notify ARM Service"
"SOFTWARE\Adobe\Adobe ARM\1.0\ARM"
"\\.\pipe\32B6B37A-4A7D-4e…"     ← 安装器与 ARM 组件间的命名管道 IPC
"TsnIorcAeBoda"                  ← 倒序混淆字符串（Adobe Acrobat… 安装标记）
```

即：除服务外，安装器还会创建名为 **"Adobe Acrobat Update Task"** 的计划任务（社区检索证实其在真实系统上的存在与触发行为：登录/周期触发 ARM 更新检查）。该任务名与 03 篇外部情报中的 Task Scheduler 指南条目一致。

## 2. 自启动面：注册表 Run 键与崩溃报告挂接

对 Registry 表 3,306 行做自启动/服务/AGS/ARM 关键词过滤，命中 30 行（`_behavior_summary.json → registry_autostart_hits`）。关键项：

### 2.1 HKLM Run 键（Root=2, `SOFTWARE\Microsoft\Windows\CurrentVersion\Run`）

| 值名 | 数据 | 绑定组件 |
|---|---|---|
| **`Acrobat Assistant 8.0`** | `"[DISTILLR]Acrotray.exe"` | `Distiller_Bin_AcroTray` |

`Acrotray.exe`（Distiller 助手托盘）随系统登录常驻。此为本 MSI 写入的**唯一传统 Run 自启动项**——克制，但存在。

PE 侧补强证据（ADelRCP.dll 字符串）：`\Adobe\ARM\1.0\AdobeARM.exe"`——ARM 更新器自身的 Run 引用路径（由 ARM 子安装器写入，不在本 MSI 的 Registry 表内，属**二阶自启动**：本 MSI 安装 ARM 组件，ARM 再写自己的自启动与任务）。

### 2.2 IE/Edge 低权限提升策略（ElevationPolicy）

```
HKLM\SOFTWARE\Microsoft\Internet Explorer\Low Rights\ElevationPolicy\{BE0A2…}
  AppName = AdobeCollabSync.exe
```

为 `AdobeCollabSync.exe`（协作/注释同步进程）注册提权策略——这是 Acrobat 安装面里对浏览器沙箱模型的显式修改点，安全审计中值得单列。

### 2.3 崩溃报告器挂接

```
HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\RuntimeExceptionHelper
  → [INSTALLDIR]Acrobat\CRClient.dll, #0
```

把 Adobe 自家 `CRClient.dll` 挂入 Windows 错误报告的运行时异常助手——崩溃数据流向 Adobe 而非仅微软。File 表确认 `CRClient.dll`（连同 `[INSTALLDIR]Acrobat\` 前缀行）在落盘清单中。

### 2.4 ARM 注册表配置群（更新基础设施的自描述）

Registry 表写入了完整的 ARM 配置键（节选）：

```
HKLM\SOFTWARE\Adobe\Adobe ARM\1.0\ARM
  iCheck = #[UPDATE_MODE]        iLogLevel = #1
  ARM_Update_3, OnDemandManifestURL…
HKLM\SOFTWARE\Adobe\Adobe ARM\Legacy\Acrobat\[ProductCode]
  Check = #[ARMCheckFrequency]   Mode = #[UPDATE_MODE]
  ManifestURL_3 = [ARMManifestLocation3]   TrackName = [RegistryHiveName]
HKLM\SOFTWARE\Adobe\Adobe ARM\Products\[WEBRCSC_ARM_REG_CODE]
  ManifestURL / ManifestURL_2 / ManifestURL_3
  ProductName = AcrobatServices  ProductVersion = [ProductVersion].0
  PolicyDisableUpdater → SOFTWARE\Policies\Adobe\Adobe Acrobat\[RegistryHiveName]\Fea…
  DisableAnyUI = #1   InstalledValidate = [INSTALLDIR]Acrobat\Acrobat.exe
```

注意 `PolicyDisableUpdater`——**ARM 自身预留了企业策略键位来停用更新器**（对应 04 篇的处置路径之一）。

## 3. 定制动作面：336 个 CustomAction 的解剖

CustomAction 表（336 行）按 Type 与 Source 聚合（列对齐局限已在 01 篇声明，聚合取自完整段）：

**Type 分布**（MSI CA 类型语义）：
- Type 51（设置属性）× 54 —— 安装参数的属性赋值链
- Type 65（Binary 表 DLL 入口调用）× 24 —— 真正执行二进制代码的动作
- Type 3137（0xC41 = 异步/提交脚本变体的 Binary-DLL）× 22
- Type 19（错误弹窗）× 3 —— 阻断性安装校验
- Type 1/321/3393/1089/98/257 等 × 少量

**Source 分布（Binary 键 → 承载动作数）**——安装行为的"引力中心"：

| Source（Binary 键） | 动作数 | 职能（结合 PE 身份与 Target 入口点） |
|---|---|---|
| **ADelRCP** | **80** | 注册表清理/所有权/PDF 关联仲裁（27 条注册表字符串：7.0/8.0 Registration 删除、PDF ownership、TOOK_OWNERSHIP_AFTER_UPGRADE…） |
| IWActs | 11 | 安装向导动作（AppsInUse/BlockingProductMatrix） |
| AdobeIsf | 6 | InstallShield 扩展动作 |
| PrintInf / InstPDFM / InstOOBELib | 5/5/5 | 打印机 INF / PDFMaker / OOBE |
| ANCUtility / AcroTgts | 4/4 | 新组件 / 旧版本目标清理 |
| AcrobatCA / PerfInst / ArmCustomActions.dll | 3/3/3 | Acrobat 专用 / 性能计数器 / **ARM 服务与任务** |
| AcroSup64 / AbcpyDll / EMI_ORIENTATION_DLL | 2/2/2 | 64 位支持 / **ABCPY.INI 部署配置** / 企业方向 |
| EXE 引用（InstallExecuteSequence 侧） | — | `acroservicesupdater.exe`、`SingleClientServicesUpdater.exe`、`acrobat_sl.exe`、`gccustomhook.exe`、`FullTrustNotifier.exe`、`CreatePDFPrinterUtility64.exe`、`Dist_acrotray.exe` |

InstallExecuteSequence（252 行）给出执行时机：Adobe 定制动作分布在标准序列的 `AppSearch`(≈842) 之后、`InstallValidate`(2300) / `InstallInitialize` / `InstallFinalize` 前后，卸载-回滚对（`*_Rollback`）成对出现——行为模式是常规安装编排，无隐藏的延迟触发器（与 02 篇外 Agent 宪法审计中"休眠触发器"的检查思路一致：**本 MSI 中未发现条件休眠/延时触发类动作**；`AppsInUse`/`BlockingProductMatrix` 等均为安装期阻断检查）。

值得单列的字符串证据：`gccustomhook.exe`（GC= Genuine Client 钩子名）与 `FullTrustNotifier.exe` 出现在 CA 引用中——AGS（Adobe 正版验证）与 Acrobat 安装链的耦合点，即 03 篇外部情报所描述"AGS 随 Adobe 产品安装/重注入"的本地对应物。本 MSI 的 Binary 表**不包含** AdobeGCClient 本体（它由 setup.exe 链或 ARM 在运行期引入），这一点以证据澄清：**AGS 不在这份 MSI 的静态载荷内**。

## 4. 落盘清单与部署配置

- **File 表 5,280 行**（8.3 短名\|长名格式）——Acrobat 主程序、AcroCEF（内嵌 Chromium：`AcroCEF_ffmpegsumo.dll`、`AcroCef_chrome_elf.dll`）、`AdobeCollabSync.exe`、`AcroBroker.exe`、`pdfshell64.dll`、PDFMaker 套件、`Ex_Bin_SQLite.dll`、`Ex_Bin_icuuc67.dll`、`RSA_ccme_ecdrbg.dll`（加密随机数）、字体/CMap/语言资源等。外部 CAB（Core/Intermediate/Extras/Optional/AlfSdPack/Languages，Media 表 6 磁盘）承载压缩载荷。
- **Directory 表 806 行**：`[INSTALLDIR]Acrobat\`、`[CommonFilesFolder]Adobe\`、`[PLUGINS_3D]` 等。
- **Component 表 2,308 行**：含 22 个 VC100–VC142 合并模块行（`117_bin_114.bin` 证据：Microsoft_VC1x0_CRT/MFC/ATL/OpenMP 各架构 GUID + 版本列 1.8.0–14.24）——Acrobat 静态捆绑整代 VC 运行库。
- **setup.ini**：`PATCH=AcrobatDCx64Upd2600221931.msp`（把 2021 基座直接补到 26.002.21931）、26 语言矩阵、对 11.0/10.1/2015 旧版本的补丁链段（`IgnoreFailure=1`）。
- **ABCPY.INI**：`[OEM Install]` 的 `ISX_SERIALNUMBER/USERNAME/COMPANYNAME/INSTALLDIR` 空模板——由 AbcpyDll.dll 消化的静默部署入口。

## 5. 小结：安装行为的完整画像

一次默认安装会落下：**1 个 SYSTEM 服务**（AdobeARMservice/armsvc.exe）+ **1 个计划任务**（Adobe Acrobat Update Task）+ **1 个 Run 自启动**（Acrotray.exe）+ ARM 组件（自带二阶自启动 AdobeARM.exe）+ 崩溃报告挂接（CRClient.dll）+ ElevationPolicy 修改（AdobeCollabSync.exe）+ 3,306 条注册表写入 + 5,280 个文件 + 整套 VC 运行库。除上述明示机制外，Registry/CA/IES 三表交叉检索未发现未声明的持久化通道；`gccustomhook.exe` 引用提示 AGS 耦合发生在运行期而非本 MSI 静态载荷。网络面（这些组件向谁报告）见 03 篇，处置方案见 04 篇。
