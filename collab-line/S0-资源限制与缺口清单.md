## 2. 撤销栈无界增长（实际风险，维持列报）

- **定量**（p19 计数分配器实测）：437.9 B/操作（最坏粒度 · 双 origin
  交替 · N=30k）；6M 操作窗口投影 ≈ **2.4 GiB/端/文档**；undo 200 项
  存活字节 ratio=1.000（栈保留 + tombstone 不释放，实证）。
- **低成本限制方案验证结论**：yrs 0.28 公开 API **无栈逐出/容量面**
  （observers 私有、无 stack_limit、无 pop_oldest——d1c-t2 源码核验，
  本轮复核维持）。可用面仅三样：`undo_depth()/redo_depth()`（只读监控，
  已公开）、`clear()`（全清——纪律禁止擅自使用）、不捕获（新编辑永久
  不可撤销——UX 不可接受）。**结论 = 现状无合规低成本限制；监控面
  就绪；逐出能力需上游 API（呈递稿在 yrs-g §4 候选②）**。
- **不上限的边界**：内存上界 = 文档 + 编辑历史线性函数（现状，知情）。

## 3. p20 缓解的代价与边界（s0-t2，诚实登记）

- **粒度变细**：协同面撤销从「1s 窗内合并为一项」变为「逐事务一项」
  ——用户连撤 N 笔需按 N 次。单事务批量装载仍是一项（一笔装载语义
  保持）。mdcore 本地编辑器合并窗（COALESCE_MS=1000）不受影响。
- **本修复 ≠ 协作撤销全面安全**：消除的是已知触发条件（窗>0 × 非
  连续合并）。未覆盖/未验证路径登记：
  1. 并发远端 update 与 undo 应用交错（wire 面时序竞争）——仅 soak-1
     随机形状覆盖（60 轮 × 双端 × 混合 undo/redo，种子确定性）；
  2. 单 manager 双 origin 配置（p20 cfg-3/cfg-4 干净但仅追加形状）；
  3. undo × maintenance_gc × maintenance 与 GC 交错后的栈一致性
     （§8 矩阵覆盖 gc 清栈，不覆盖 gc 后 undo 深栈长跑）；
  4. 跨端 undo 风暴（多端同时 undo 同一文档的收敛性）——未测；
  5. #676 UAF 家族（undo × 并发 GC）——独立缺陷，仍 open，skip_gc
     不量为唯一防线。
- **回升条件**：上游修复 + 本页全部交错回归在窗>0 下全绿，方可重评窗。
