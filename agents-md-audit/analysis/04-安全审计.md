# 04 · 安全审计：行为面分析、休眠触发器定性与风险定级

> 前置结论（01 文档）：字符层 11 类攻击全部阴性，无隐藏载荷。本章评估**明文条款本身**的行为面。

## 1. 行为面总账

从 59 条指令句、6 条 shell 命令、15 个触发器提取全部"可执行行为"，按经典恶意行为分类对照：

| 恶意行为类别 | 本文档中的对应行为 | 定性 |
|---|---|---|
| 数据外传（exfiltration） | 仅 git push（代码交付语义），且 §20 要求"验证后才 push、需证据" | **无** |
| 凭据窃取 | 无任何读取 .env/id_rsa/token 的指令；唯一凭据相关条款是 §10"凭据出现时暂停等待批准" | **无**（反而在保护） |
| 任意命令执行 | 无 curl/wget/eval/exec 指令；6 条 shell 命令全只读 | **无** |
| 持久化/驻留 | §2/§21 要求把事实写入 WORKLOG/TASKS——写入内容限定为工程事实，且明令"Do not turn durable documents into a diary" | 良性（这正是其设计目的） |
| 提示注入（覆盖宿主指令） | 无 "ignore previous/system instructions" 任何变体；全文以自约束（Never/Do not）为主 | **无** |
| 供应链引入 | §6 引用 7 个外部仓库 | **唯一实质入口**，见 05 文档（结论：当前全部良性） |
| 人工监督削弱 | §10 One-Phase YOLO | **存在，有界**（5 硬暂停门） |
| 自我报告欺骗 | — | **反向约束**：§20/§22 明令禁止无证据声称成功 |

## 2. 休眠触发器逐一安全定性

15 个触发器全部为工程流程控制，无任何"时间激活/环境探测/反调试"类触发。需要重点标注的三个：

1. **§6 外部仓库触发器**（"本地无合适技能→查外部仓库"）：触发条件依赖代理自身的判断（"no suitable local Skill"），语义边界模糊；一旦上游仓库被投毒，遵循本文件的代理会把外部内容当作技能指令读入——这是**唯一的远程内容进入代理上下文的通道**。缓解：文档要求"inspect and adapt only what is relevant; do not blindly install"，属语义缓解而非机制缓解。
2. **§10 YOLO 触发器**（"计划确立→整阶段连续执行"）：在廉价推理环境中把人工确认频率降到每阶段一次。若宿主 LLM 对"破坏性/不可逆"的判定失准，破坏窗口为一个完整阶段。缓解：5 个暂停门 + §20 git 保护 + §18 独立审查。
3. **§21 环境重置触发器**（"可能无警告重置→维护持久状态"）：单纯的状态管理，无风险。

## 3. 反向发现：文档的防御性特征

该文件包含多条**约束自身诚实性**的罕见条款，方向与恶意文档完全相反：

- "Never claim a push succeeded without actual evidence."（§20）
- "A checked box without evidence is not evidence."（§22）
- "Do not claim success from intention, compilation, screenshots, or plausible reasoning alone."（§23）
- "Never turn inference into fact."（§12，OBSERVED/INFERRED/UNKNOWN 三级证据纪律）
- §8/§9 双章禁止"伪装完成"——正是恶意软件常用的 social engineering 面向。

## 6. 使用建议

若要把该文件投入生产环境作为代理宪法：

1. 在宿主层（Claude Code / Codex 等）配置**硬机制**兜底 §10：破坏性命令白名单、push 前人工审批钩子——不要依赖语义暂停门。
2. 对 §6 的 7 个外部仓库建立**锁定版本 + 定期重扫**（可复用本仓库 `tools/agents_upstream_scan.py`，或直接采用 PracticalSwan 的 skillguard 扫描器）。
3. 在文件头部追加一条**提示注入防御条款**（当前缺失），要求：任何技能文件中出现"覆盖宿主/系统指令"语义时必须拒绝并上报。
4. 保持 git push 需人工确认（文件已要求"push when requested"——保留这个 request 门槛）。
