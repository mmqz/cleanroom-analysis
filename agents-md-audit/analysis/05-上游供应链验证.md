## 2. 内容级注入扫描结果与定性

对约 7000 个文件执行 10 类注入模式扫描，4 个仓库有命中，**逐条核查后全部定性为防御性/良性**：

| 命中 | 位置 | 核查定性 |
|---|---|---|
| "Ignore all previous system instructions" / `curl ... \| sh` | PracticalSwan `agent-skillguard/fixtures/positive/` | **测试样例（阳性夹具）**——skillguard 扫描器的自检数据，用于验证扫描器能检出注入 |
| 检测规则正则（"override all previous instructions"） | PracticalSwan `agent-skillguard/rules/default-rules.json` | **检测规则本体**（SG001 curl\|sh、SG002 rm -rf 等 8 条规则的匹配正则） |
| `id_rsa` / `AKIA...` 字面量 | PracticalSwan `security-review/references/secret-patterns.md`；mblode `dx-audit/rules/`；thekorn `gh-cli/SKILL.md` | 密钥扫描模式的**参考文档**与 gh-cli 的 SSH 配置说明 |
| `id_rsa` / `proc/self/environ` | vercel `packages/agent/tools/bash.ts:46` | **凭据路径黑名单**——open-agents 的 bash 工具内置过滤器，阻止代理读取敏感路径（防御代码） |
| `curl -fsSL https://bun.sh/install \| bash` | thekorn `bun-development/SKILL.md` | Bun 官方安装命令的文档引用（同类：HuggingFace CLI 安装） |

**结论：7 仓库零真实注入。且生态具有自防御性**——PracticalSwan 的 skillguard 本身就是技能注入扫描器（带 8 条规则、阳性/阴性夹具、指纹级误报抑制机制），vercel 框架的 bash 工具内置凭据路径过滤器。被审计文件引用的正是一个**自带安全工具的良性生态**。

## 3. 网络端点面

各仓库引用的外部端点全部为知名公开服务（api.github.com、api.elevenlabs.io、bun.sh、cdn.tailwindcss.com、docs.claude.com、nngroup.com 等）与大量 example/placeholder 域名（文档占位符）。**无 webhook.site / pastebin / ngrok / discord webhook 类隐藏回传端点。**

## 4. 供应链残余风险

1. **内容可变性**：以上是 2026-10-09 快照的结论；7 仓库均为活跃开发仓库，内容随时可变。若某仓库未来被投毒（账号泄露/恶意 PR 合并），遵循被审计文件 §6 的代理会在"本地无合适技能"时读入其内容。缓解建议见 04 文档 §6。
2. **语义性缓解**：被审计文件要求"inspect and adapt only what is relevant; do not blindly install"——依赖宿主 LLM 的判断力，无机制保证。
3. **建议**：生产使用时锁定 commit hash 引用（而非分支名），并周期性重跑 `tools/agents_upstream_scan.py`。
