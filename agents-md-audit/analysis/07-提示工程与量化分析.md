## 2. 六项已验证的提示工程技术

### 2.1 首尾双锚（primacy + recency anchoring）

LLM 对提示词**开头与结尾**的内容给予显著更高的注意力权重。本文件的利用方式：
- **开头（Purpose + §1）**：身份定义 + 不可协商管线 + 唯一全程加粗句 "Evidence beats assertion"；
- **结尾（Final Rule）**：7 条全部加粗的律令，37‰ 否定密度（全文档第五高），把 23 章压缩成 19 行重申。

首尾之间是细节正文——即使中段条款被弱化，首尾锚仍保住核心行为约束。

### 2.2 伪代码作为策略语言

21 个代码块中 20 个是伪代码（管线 `A → B → C`、层级 `A > B > C`、枚举、检查清单、模板）。这利用了 LLM 的两个特性：①对**结构化序列**的遵循率高于散文规则；②围栏块在训练数据中大量对应"可执行规范"，模型对其中内容的"照办倾向"更强。伪代码同时压缩了 token（§1 的 13 步管线只用 14 行）。

### 2.3 条件激活式（休眠触发器）

35 个条件式构成 15 个完整子协议的触发条件（见 03 文档 §3.3）。这在提示工程中相当于**惰性加载（lazy loading）**：不需要在每次会话都激活全部规则，只在语义条件满足时生效——既省注意力预算，又让规则之间的互斥（如 §7 前端工作流 vs §16 调试协议）不会同时抢占行为路径。

### 2.4 认识论约束（对抗幻觉的词汇表）

§12 的 OBSERVED / INFERRED / UNKNOWN 三级标签 + §17/§23 的 `[NOT VERIFIED]` / `[PASS]` / `SUCCESS / FAILED` / `COMPLETED / PARTIALLY VERIFIED` 固定枚举——这是**强迫模型使用封闭词汇表自我标注**。封闭枚举的妙处：它把"诚实性"从道德要求（模型常绕过）转化为格式要求（模型极难绕过——不填枚举就违反模板）。

### 2.5 反断言条款（对抗自我报告美化）

三处递进式封堵代理美化自己：§20"无证据不得声称 push 成功"→ §22"勾选框不是证据"→ §23"不得仅凭意图、编译、截图或貌似合理的推理声称成功"。后一条点名了 LLM 自我报告的四个典型幻觉源——作者显然实测过 coding agent 的失败分布。

### 2.6 负面清单的统计性精准

三份黑名单的命中率说明作者对 LLM 退化模式的深度经验：
- §7 的反 AI UI 七连禁——精确对应 2024–2026 年 AI 生成前端的统计性审美（紫蓝渐变、玻璃卡片、hero+三卡片）；
- §9 的 11 类降级形态——覆盖了"演示驱动开发"的全部作弊面；
- §14 的 7 类过度抽象——与 LLM 训练数据中大量演示性工厂/管理器代码的惯性一致。

三个结构性发现：
1. **流程章节（§17/§18/§22）零否定式**——纯正面清单。作者对"怎么做"用程序、对"不许怎么做"用禁令，两种语体的分工非常干净；
2. **反过度双子章（§14/§15）+ §12 是否定密度峰值区**——作者最担心的三类失败：过度工程、过度防御、把推断当事实；

## 4. 与宿主注意力预算的兼容性

≈3,050 token 的系统提示词在 Claude/GPT/Codex 级别的 200k 上下文中占比 ~1.5%——足够小以维持指令权重，足够大以覆盖 15 个子协议。135 行列表 + 21 个代码块的结构化率极高，连续散文段落极少（主要出现在动机声明处，如 §10 开头的 "This environment may provide inexpensive/free model calls but limited continuity"——先给理由再给规则的顺序也符合说服心理学的"理由先行"模式）。
